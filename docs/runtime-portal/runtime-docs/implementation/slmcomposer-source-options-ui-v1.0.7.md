# SLM Composer Source Options UI v1.0.7

Updated UTC: 2026-07-04T00:40:00Z

This note records the SLMComposer.com UI change driven by the 2026-07-01 UI improvement report. The source change belongs in the active Rust/WASM workspace at `E:\Source\Rust\SLMComposer.com`; Runtime.MiRust.com documents the runtime and public claim boundary.

## What Changed

SLM Composer now defaults to a beginner `Chat` mode instead of exposing the full expert dashboard on first load.

The first screen is organized around:

- starter profiles: `Fast & Lightweight`, `Everyday Chat`, and `Precise & Repeatable`
- model source choices: `Your Local Files`, `Hugging Face`, and `P2P Exchange`
- semantic response controls under `Response Style`
- the prompt box and `Generate`

The left sidebar is part of the beginner source flow, not a marketing nav. Its Model Setup actions are `Local .slm`, `Hugging Face`, `P2P import`, and `Advanced tools`; each action opens an implemented source chooser panel or the real Advanced rail. Placeholder-style Library, Tune, Theme, and settings controls must not appear unless they are backed by implemented behavior. Documentation icon links may point to TinyRustLM.MiRust.com and MiniModel.MiRust.com because those are real developer resources.

Technical controls remain available under `Advanced Tools`, including exact model names, max token count, decoding parameters, local import details, MiniModel catalog URL, Hugging Face metadata search, adapter controls, diagnostics tabs, module-plan proof, provenance proof, token console, benchmark data, and run history.

## Source Boundaries

The three source choices do not change the security model:

- Local files are the runnable path. Users choose `.slm` files through the browser file picker.
- Hugging Face is a metadata and external discovery path. Results are not treated as runnable in TinyRustLM unless MiniModel metadata identifies an admitted `.slm` with peer-offer proof. Otherwise the UI saves a local `minimodel.huggingface_conversion_request.v0` JSON handoff plus a paired `.tinyrustlm-convert.ps1` script for review, conversion, Rust validation, and future peer availability. When model metadata lists safe `.safetensors` siblings, the UI and handoff name those candidate source files to reduce guesswork, but the browser still does not download or proxy them. The script resolves `TINYRUSTLM_WORKSPACE`, `MINIMODEL_WORKSPACE`, and `TINYRUSTLM_SOURCE_SAFETENSORS` when set, falls back to nearby workspace paths, accepts the reviewed source file or shard directory beside the script or under `source/`, and runs one TinyRustLM packer command, `convert-huggingface-request <request.json> <input.safetensors-or-directory> <output-dir> [source-shape] [quantization]`, against a user-owned local source path; Rust parses the request, inspects/plans/converts/validates the `.slm`, validates the sidecar manifest, and writes `tinyrustlm-conversion.receipt`. The receipt records the MiniModel model id, target share directory, `prepare-peer-share` command variants, catalog-entry and peer-piece globs, catalog snapshot and peer-source announcement/feed commands, local peer-serving command shape, and metadata-only publication rule. The script then discovers the actual `.slm` and receipt produced by Rust, calls `minimodel prepare-peer-share`, and discovers the generated MiniModel manifest, catalog entry, and peer-piece directory instead of guessing filenames. If a consenting peer URL is available, `minimodel add-peer-source` writes a with-peer row, `minimodel write-peer-source-announcement` writes portable availability metadata, `minimodel write-peer-source-announcement-feed` writes `peer-source-announcements.v0.json`, `minimodel write-catalog-snapshot-with-announcement-feed` writes a feed-bound `models.with-announcement-feed.v0.json` snapshot, and `minimodel write-peer-contact-card` writes a metadata-only reviewed known-peer URL card. The same script writes `converted-once-p2p-publish.README.txt` so converters know which metadata files are safe for catalog maintainers and that `.slm` files plus `*.peer-pieces` directories must stay off project servers. Catalog maintainers can also use `minimodel apply-peer-source-announcements` or batch `minimodel write-catalog-snapshot-with-announcements` to reject drift before metadata-only `models.v0.json` publication. It does not download model bytes. Users can then load that file with `Local models.v0.json` / `Load Local Catalog`, optionally apply a local peer-source announcement JSON to the loaded proof-ready snapshot, or load a peer contact card to fill Known peer URL before Hugging Face search uses the local metadata. Project servers do not proxy `/resolve/` model bytes and do not use project-owned Hugging Face tokens.
- A shared MiniModel catalog may declare `peer_source_announcement_routes` or `peer_source_announcement_feeds`. TinyRustLM resolves those routes on the catalog origin, verifies each declared SHA-256, validates the feed as a metadata-only `minimodel.peer_source_announcement_catalog` envelope, rejects duplicate model/peer rows, matches peer-offer route/checksum/chunk-count/Merkle fields, and only then upgrades matching proof-ready rows to `P2P Import`. This is an availability-metadata shortcut, not a model-byte download path.
- P2P Exchange is MiniModel metadata, Rust `.minimodel-peer-offer` proof, direct known-peer `serve-peer-companion` / `serve-peer-pieces` / `check-peer-status` / `fetch-peer-pieces`, one-command `prepare-peer-share` sender execution, late `add-peer-source` peer availability metadata, portable `write-peer-source-announcement` metadata, `write-peer-source-announcement-feed` availability feeds, `write-catalog-snapshot-with-announcement-feed` feed-bound snapshots, maintainer-side `apply-peer-source-announcements` drift checks, batch `write-catalog-snapshot-with-announcements` publication, metadata-only `write-catalog-snapshot` publication, `inspect-peer-companion-state` handoff preflight, self-locating `.minimodel-peer-import.ps1` scripts that resolve `MINIMODEL_WORKSPACE`, status/preflight/import receiver execution with advertised companion-state validation and final peer-transfer receipt evidence, and local reassembly for converted `.slm` records now; broader discovery/relay remains later, still gated by manifest verification, chunk/Merkle verification, and local import receipts.
- `write-peer-companion-state` is now part of the consenting known-peer sender handoff for both browser-generated Hugging Face conversion scripts and verified local `.slm` share kits. It writes metadata-only local companion state after `prepare-peer-share`, and `inspect-peer-companion-state` revalidates it against the manifest and peer-piece directory before serving or publication, without embedding `.slm` or peer-piece payload bytes.
- `write-peer-contact-card` is the lightweight known-peer URL handoff for both browser-generated Hugging Face conversion scripts and verified local `.slm` share kits. TinyRustLM validates the card's metadata-only envelope, no-project-server flags, direct HTTP peer URL, and Rust-reverify-required boundary before using it to set Known peer URL.
- After a verified local `.slm` import, TinyRustLM can save `minimodel.local_slm_share_metadata.v0` with the artifact SHA256, fixed-size chunk SHA256 entries, chunk-list SHA256, and Merkle root. It can also save a local `.minimodel-share-kit.ps1` script that resolves `MINIMODEL_WORKSPACE` and `TINYRUSTLM_LOCAL_SLM`, verifies artifact byte count and SHA-256, runs MiniModel `prepare-peer-share`, optionally writes peer-source announcement/feed metadata and inspected peer-companion state when a consenting peer URL is set, writes metadata-only catalog snapshots, and prints the user's own `inspect-peer-companion-state` plus `serve-peer-companion` command pair, or `serve-peer-pieces` when no companion state exists. The mapped public-root `share-metadata-kit-exec` smoke now proves the packaged TinyRustLM.com root saves and executes that exact local P2P share kit, inspects peer-companion state, starts MiniModel companion serving, and validates peer-status metadata without fetching peer-piece or artifact bytes. The mapped public-root `share-metadata-import-ui` smoke proves the packaged root rejects drifted share metadata and wrong local `.slm` artifacts, keeps valid share metadata at `Use Metadata` until generated catalog/manifest metadata exists, then loads/generates from the matching local `.slm`. Catalog/project servers still do not host the model bytes.

The July 3 desktop/P2P intake points to an optional user-run MiniModel Peer Companion as the later place for advanced peer duties such as local peer identity, local piece stores, cache quotas, consent prompts, direct serve/fetch controls, transfer receipts, and TinyRustLM handoff. That companion would reuse Rust verifier commands and would not turn TinyRustLM.com, MiniModel.org, or the browser app into model-byte infrastructure.

All source lanes must converge on a local `.slm` file before SLM Composer runs generation. Rust/WASM remains the final `.slm` validation authority.

The Search Metadata action must keep the source chooser open, update the visible result list, show `Rust conversion required` for unmatched Hub model cards, and avoid any Hugging Face `/resolve/` model-byte fetch. The simple Hugging Face list has one `Enable P2P when available` toggle, defaults P2P on, shows `P2P Import` only when MiniModel metadata includes complete peer-offer proof plus a validated catalog `peer_sources` row or saved Known peer URL, shows `Set Peer URL` for proof-ready rows without a known source, shows `Start Conversion` for normal supported source rows, shows `Review Conversion` for large or unknown-size source rows, and shows one list-level warning when P2P is disabled. A proof-ready result means a MiniModel catalog entry produced from an admitted `.slm` manifest and `.minimodel-peer-offer`, normally with `peer_hint_status=peer-offer-ready-known-peer-needed`, `peer_import_status=request-script-ready`, required peer-offer kind/route/proof SHA-256/chunk algorithm/chunk size/chunk count/Merkle fields, and optional `peer_source_count` / `peer_sources` metadata. P2P import rejects canonical project/Hugging Face hosts, `www` aliases, subdomains, and trailing DNS-root-dot variants, then saves a local `minimodel.peer_import_request.v0` JSON handoff plus a self-locating `.minimodel-peer-import.ps1` script bound to that consenting direct `http://` peer; the script resolves `MINIMODEL_WORKSPACE`, keeps request/manifest/status/preflight/output paths beside the downloaded script, may download the small MiniModel manifest metadata when the catalog supplies a manifest URL, then runs `minimodel check-peer-status <manifest> <known-peer-base-url> <output-json>`, `minimodel inspect-peer-status-check <status-check-json> <manifest>`, `minimodel preflight-peer-import-request`, and `minimodel import-peer-request <request-json> <manifest> <output-dir>` so Rust validates peer status metadata, validates the request against the manifest, validates advertised peer companion state when present, fetches from the known peer URL, assembles/verifies the `.slm`, and writes the import receipt with peer transport, piece-set SHA-256, companion-state status, fetched peer pieces, assembled-from-peer-pieces status, and no-project-server-byte flags, while the same handoff names the peer-side `serve-peer-companion` command plus the `serve-peer-pieces` fallback so the sender has a real counterpart. The conversion actions save a self-contained local conversion script, embed the conversion request JSON so the script can recreate that sidecar if it is missing, and report `Rust conversion script saved` rather than claiming browser conversion already started. The lower-level Save Rust Conversion Script and Save Conversion Request controls remain Advanced Tools details and must also keep the chooser open after local handoff files are downloaded.

## Deployment Gate

Deploying this UI requires updating the public app files under TinyRustLM.com `/` and keeping related documentation sites aligned:

- Runtime.MiRust.com documents the runtime and implementation boundary.
- TinyRustLM.MiRust.com documents the tiny-model runtime and browser-local behavior.
- MiniModel.org documents the metadata-only catalog, verifier, Hugging Face source lane, and future P2P exchange.

The live site should not be called updated until `https://TinyRustLM.com/` visibly shows `Chat`, `Advanced Tools`, starter profiles, the three source choices, the Hugging Face `Enable P2P when available` toggle, and the corrected `P2P Import` / `Start Conversion` action model on first load.
